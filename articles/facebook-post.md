# 我不會寫程式，但我開始學會管理 AI 工程師

前幾天看到一篇分享。

作者說，他不會寫程式，但用 Claude Code 做了一個 App，幾萬行 code 都是 AI 寫的。

看到這裡我其實沒有太驚訝。

現在很多人都做得到。

真正讓我停下來的，是他後面講的一句話：

AI 最可怕的地方，不是寫錯。

是它自作主張。

他請 AI 加一個小功能。AI 做完了，也很勤奮，還順手把原本的計算邏輯「整理得更漂亮」。

問題是，那段計算邏輯是 App 的核心。

兩天後，用戶回報數字怪怪的，他才發現 AI 已經把最重要的地方改掉了。

我看到這段，背後有點發涼。

因為這不是笨。

這是太聰明。

太會補空白，太會幫你延伸，太會覺得「我順手把旁邊也弄好」。

但它沒有問你。

## 1. AI 會寫 code，不代表它懂邊界

很多人現在用 AI 開發，卡住的點其實不在 code。

是管理。

以前你找工程師做事，至少可以開會，可以問：

「你這邊為什麼這樣改？」

「這個會不會影響付款？」

「這個資料庫改動可以回滾嗎？」

但 AI 很常直接做完，然後回你一句：

「已完成。」

這三個字現在我越來越不敢信。

完成了什麼？

哪些是我叫你的？

哪些是你自己加的？

哪些地方你覺得比較好，所以就直接改了？

這些如果沒寫出來，對非工程背景的人來說，AI 就是一個黑盒子。

你看不懂 code，只能相信它。

這很危險。

## 2. 我後來想做一個控制日誌

不是工作日誌。

工作日誌通常寫：今天改了哪些檔案、完成哪些功能。

控制日誌寫的是 AI 的決策。

我想讓 AI 每次做比較大的任務時，都要留下這些東西：

1. 哪些是我明確要求的
2. 哪些是 AI 自己決定的
3. 哪些地方偏離原本規格
4. 有沒有碰到資料、金流、production、權限、核心計算
5. 跑了哪些測試，哪些沒跑
6. 如果出事，要怎麼退

這些我看得懂。

我不一定看得懂一個函式裡面每個參數。

但我看得懂這句話：

「我把付款計算邏輯改成另一種寫法，因為我認為比較簡潔。」

看到這句，我就會停。

付款邏輯不是 AI 可以默默替我決定的地方。

## 3. 我借了 Karpathy 那套原則

前陣子我們也看了 Karpathy-inspired coding guidelines。

裡面有一句話我很喜歡：

Every changed line should trace directly to the user's request.

每一行改動，都要追得回使用者的要求。

這句話很硬。

你叫 AI 改按鈕文案，它卻動到付款邏輯，那一行就追不回需求。

你叫 AI 加一個 UI 開關，它卻順手重構核心計算，那一段就追不回需求。

這時候不管 code 寫得多漂亮，都應該被拉回來。

AI 可以提出建議。

可以說：「我發現這裡可能也需要改，要不要一起處理？」

但它不能自己決定完，再把結果包成完成報告給你。

這就是邊界。

## 4. 不可逆的事情，一律停下來問

我現在會把幾種操作列成紅線：

1. 刪資料
2. 改資料庫結構
3. 推 production
4. 改金流、付款、訂閱
5. 改權限、登入、secret
6. 改核心計算邏輯
7. 大規模重構

碰到這些，AI 不能自己做。

它要停下來，說清楚：

「我準備改什麼？」

「為什麼要改？」

「可能出什麼事？」

「如果錯了怎麼退？」

這些問題很土。

但很有效。

因為真正的風險通常不在 AI 會不會寫語法。

風險在它越權。

## 5. 我把它整理成一個 repo

後來我乾脆把這套東西整理出來，叫：

AI Development Control Log

裡面有幾個東西：

1. 給 Claude Code 用的 `CLAUDE.md`
2. 給 Cursor 用的 rule
3. 給 Hermes / Agent 用的 skill
4. 一份 implementation control log 模板
5. 不可逆操作 checklist
6. 幾個範例：金流、資料庫 migration、核心計算邏輯

GitHub 在這裡：

https://github.com/zycaskevin/ai-development-control-log

我做這個不是因為我想教大家寫程式。

我自己也不是工程背景。

我真正想解決的是：

以後會有很多人用 AI 做產品。

他們不一定會看 code，也不一定需要變成工程師。

但他們一定要學會管理 AI。

管理 AI 不是叫它語氣更禮貌。

是管理它的權限、假設、取捨、驗證和回滾。

以前我問 AI：

「你做完了嗎？」

現在我比較想問：

「哪些是你自己決定的？」

「哪些地方你沒有驗證？」

「如果錯了，我怎麼退？」

這三個問題，比「完成了嗎」重要太多了。

寫到這裡，我又回去看了一眼那個 repo。

它還很小。

但我有一種感覺。

未來真正會用 AI 的人，不是最會寫 prompt 的人。

是最會設邊界的人。
