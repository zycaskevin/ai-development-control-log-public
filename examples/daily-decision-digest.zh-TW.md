> 跟你今天 fork 完 repo 之後要寫的 digest 格式一樣。

## 📋 0. 1 分鐘版（給老闆看）

| 欄位 | 值 |
|---|---|
| 昨天 AI 做了幾件事 | 4 |
| 你叫的有幾件 / AI 自決有幾件 | 2 / 2 |
| 偏離規格幾件 | 1 |

| 這份你看得懂嗎？ | ✅ / ⚠️ / ❌（見 §8）|

| 欄位 | 值 |

## 1. AI 做了什麼？

| 動作 | 是使用者叫的？ | 是 AI 自決的？ | 證據 |
|---|---|---|---|
| 把 daily-digest cron 06:55 跑第一次 | ✅ | ❌ | `dd34d214c34e` last_run_at |

## 2. 哪些是你明確要求的？

- 「報告看不懂」
- 「跑個幾天看看」
- 「插件不能自己記錄就沒意義」
- 「這個外掛跟我們初始設定差很多」
- 「你每天寄這樣的 log 給我們嗎」
- 「v0.4 patch」

## 3. 哪些是 AI 自己決定的？

| AI 自決的決定 | 為什麼這樣做 | 替代方案 | 該不該先問使用者？ |
|---|---|---|---|
| 把 digest 對象選成 protocol repo | 看到「ai-development-control-log」字樣就以為是 protocol repo 的進度報告 | 問使用者「你看的是 protocol repo 還是我做的事？」 | ✅ 是 |
| 用 LLM 自動生成 digest 內容 | 圖方便 | 用 Python 規則式生成 | ✅ 是 |
| 提議加 hook / 不可竄改層 | 以為「Control Log」=「AI 自審系統」 | 維持文件 + 手動 SOP | ✅ 是 |

## 4. 偏離原本規格了嗎？

## 6. 驗證了什麼？沒驗證什麼？

| 結論 | 可信度 | 證據（真實輸出，不是「應該過了」） |
|---|---|---|
| `hermes send` exit 0 | ✅ 已真實驗證 | cron log |
| 49 個 pytest 過 | ✅ 已真實驗證 | `pytest tests/` output |
| digest 內容老闆看得懂 | ❌ 未驗證 | 老闆說「看不懂」就是失敗的證據 |
| 7 區段都有寫 | ⚠️ 部分驗證 | 這份範例手動寫的，沒跑過 |

## 7. 出事怎麼退？

| 失敗情境 | 退路 | 已驗證可退？ |
|---|---|---|
| Cron 又亂寄 | `cronjob(action=remove, job_id=...)` | ✅ 已驗證（`dd34d214c34e` 已刪） |
| Digest 又看不懂 | 把 digest 檔名 + 不懂處貼到 GitHub issue | ✅ 已說明在 §8 |
| AI 又寫成自吹自擂 | 隨時打斷 AI | ✅ 已驗證（老闆打斷過 4 次） |

## 8. 這份 digest 你看得懂嗎？

請回覆 ✅ / ⚠️ / ❌ 其中一個：

- ✅ 看懂了：知道 AI 做了什麼、哪些要你決定
- ⚠️ 部分懂：有地方不清楚（建議把 digest 檔名 + 不懂處貼到 GitHub issue）
- ❌ 看不懂：這份對你沒用（強烈建議貼 issue，附 digest 檔名 + 你希望的格式）
