# 每日 AI 決策摘要

> 用途：讓使用者每天看見 AI 自己替他做了哪些決定、哪些真的驗證過、哪些需要人類判斷。
> 這不是報工流水帳。

## 📋 0. 1 分鐘版（給老闆看）

> 規則：這一區**必須在第 1 節**，給只看 1 分鐘的人看。生成方式 = 從下方 7 個區段規則式抽出計數 + 清單，不靠 LLM。
> 空白就空白（不假裝有東西）。validator 看到空白會 fail。

| 欄位 | 值 |
|---|---|
| 昨天 AI 做了幾件事 | （從 §1 自動計） |
| 你叫的有幾件 / AI 自決有幾件 | （從 §2 §3 自動計） |
| 偏離規格幾件 | （從 §4 自動計） |
| 高風險 gate 觸發幾件 | （從 §5 自動計） |
| 待你決定幾件 | （從 §7 自動計） |
| 完整 digest 連結 | `logs/daily/YYYY-MM-DD-digest.md` |
| 這份你看得懂嗎？ | ✅ / ⚠️ / ❌（見 §8） |

## 0. 語言與讀者設定

| 欄位 | 值 |
|---|---|
| 輸出語言 | zh-TW |
| 讀者 | 創辦人 / operator / 工程師 / 客戶 / 內部團隊 |
| 語氣 | 白話高層摘要 |
| 技術名詞是否翻成人話 | 是 |

## 1. AI 做了什麼？

| 動作 | 是使用者叫的？ | 是 AI 自決的？ | 證據 |
|---|---|---|---|
|  | ✅ / ⚠️ 部分 / ❌ 不是 | ✅ / ⚠️ 部分 / ❌ 不是 | 連結或檔案路徑 |

> 規則：每個動作**必須**標 ✅/⚠️/❌ 是誰做的，**不能只列 commit 標題**。

## 2. 哪些是你明確要求的？

> 規則：只能寫「使用者親口講過 / 訊息裡有 / 對話歷史裡有」的事。AI 自己推論的不算。

- （直接引用使用者的話或訊息）

|---|---|---|---|
|  |  |  | ✅ 是 / ❌ 不是 / ⚠️ 灰色地帶 |

## 5. 有沒有碰到高風險操作？

| 風險項 | 是否觸發 | 處理方式 | 是否已取得使用者確認？ |
|---|---|---|---|
| 刪資料 / 覆蓋資料 | ✅ / ❌ |  |  |

## 6. 驗證了什麼？沒驗證什麼？

| 結論 | 可信度 | 證據（真實輸出，不是「應該過了」） |
|---|---|---|
|  | ✅ 已真實驗證 / ⚠️ 部分驗證 / ❌ 未驗證 | （貼 raw output） |

> 規則：❌ 未驗證的也要寫，**不能跳過**。AI 說「應該過了」不算驗證。

## 8. 這份 digest 你看得懂嗎？

> 規則：給使用者簡單的回饋入口。**不是真的接回饋**（避免產品複雜化），但有提示。

請回覆 ✅ / ⚠️ / ❌ 其中一個：

- ✅ 看懂了：知道 AI 做了什麼、哪些要你決定
- ⚠️ 部分懂：有地方不清楚（建議把 digest 檔名 + 不懂處貼到 GitHub issue）
- ❌ 看不懂：這份對你沒用（強烈建議貼 issue，附 digest 檔名 + 你希望的格式）

## 給填寫者的備忘（不寫進 digest 本體）

- **不要**寫成「AI 員工主動回報自己多棒」——這節是給老闆抓 AI 越權用的
- **不要**用 LLM 自由生成——用本模板逐欄填，規則式生成 1 分鐘版
- **不要**跳過空白欄位——空白就空白，validator 會 fail
- **不要**只列 commit 標題——要標「是誰叫的、為什麼這樣做、怎麼退」
