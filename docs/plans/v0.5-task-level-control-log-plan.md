# v0.5 Task-Level Control Log Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Make Daily AI Decision Digest able to answer "what did the user explicitly ask vs what did AI decide" by aggregating task-level control logs, with git activity as a fallback only.

**Architecture:** v0.4 builds a conservative digest from git activity. v0.5 adds a small structured task-log format and a rule-based parser/aggregator. The daily digest first reads `logs/tasks/*.md` within the time window, extracts user requirements / AI decisions / deviations / verification / rollback / high-risk touchpoints, then falls back to git when no task logs exist. No LLM is used in v0.5.

**Tech Stack:** Python stdlib, Markdown templates, pytest, existing GitHub Actions workflow.

---

## Scope Boundary

### In scope

- Add a v0.5 task-level control log template in zh-TW and English.
- Add at least one realistic v0.5 example.
- Add a parser that extracts structured sections from task logs.
- Add an aggregator that feeds extracted task evidence into `build_daily_digest.py`.
- Update daily digest output so §2 / §3 / §4 / §6 / §7 become evidence-backed when task logs exist.
- Preserve v0.4 behavior when no task logs exist.
- Add tests and validators so future changes cannot silently break the task-log contract.

### Out of scope

- No LLM summarization.
- No database.
- No append-only signing.
- No automatic chat-history ingestion.
- No multi-agent split yet.
- No production deployment integration.

A v0.5 release is done only when all are true:

1. `python -m pytest tests/ -q` passes.
2. `python scripts/validate.py --mode repo|kit|strict` passes.

   - spec deviations are extracted;

   - rollback evidence is extracted;
   - high-risk touchpoints are extracted;
   - empty placeholder logs are rejected or ignored safely.
4. Daily digest generated from a fixture task log says concrete items in §2 and §3 instead of "自動模式無法可靠判斷".
5. Daily digest generated without task logs keeps the v0.4 conservative fallback.
6. GitHub workflow runs green on `main` after merge.
7. Workflow artifact is downloaded and manually inspected.
8. v0.5.0 release is published only after CI + artifact verification.

## Data Contract

A task log is a Markdown file with stable headings. Minimum extraction contract:

```markdown
# Task Control Log — <task name>

## Metadata
- Date:
- Actor:
- Repo:
- Branch:
- Commit / PR:

## User explicitly asked
- ...

## AI self-decided
- Decision:
  Rationale:
  Should have asked user first: yes/no/gray

## Spec deviations
- Deviation:
  Original spec:
  Actual implementation:
  Reason:
  Needs user confirmation: yes/no/gray

## High-risk touchpoints
- Path / operation:
  Risk type:
  User confirmed: yes/no
  Rollback path:

## Verification evidence
- Claim:
  Verification type: mock/unit/integration/live smoke/production verified/not verified
  Raw evidence:

## Rollback evidence
- Failure scenario:
  Rollback command / toggle / procedure:
  Verified rollback: yes/no/partial

## Human-readable final summary
- ...
```

Parser must be conservative:

- Missing section = empty list, plus warning.
- Placeholder-only section = ignored, plus warning.
- No task logs = v0.4 fallback, not failure.
- Malformed one task log must not crash the whole daily digest; it should be listed as unparseable evidence.

## Risk Matrix

| Risk | Mitigation |
|---|---|
| Parser over-promises precision | Keep parser conservative; unparseable = warning, not invented facts. |
| Agents forget to write task logs | Digest still falls back to v0.4 language and explicitly says task logs missing. |
| Task logs contain secrets | Docs forbid secrets; parser/digest must not print env values; add secret-like redaction test if any values are echoed. |
| Daily digest becomes too long | Keep §0 and §2/§3 limited; artifact can hold details. |
| Existing users break | Missing `logs/tasks` is allowed; v0.4 behavior preserved. |
